# Дневник тренировок

Личный дневник силовых тренировок в виде PWA: открывается в браузере телефона, ставится на домашний экран и работает офлайн. Бэкенда и регистрации нет, все данные хранятся на устройстве (IndexedDB).

- **Цикл из 6 дней.** Цикл не привязан к дням недели, состав дней редактируется как шаблон слотов.
- **Своё расписание.** Любой день цикла ставится на любую дату, тренировки можно переносить и пропускать. Приложение подсказывает следующий по порядку день, и пропуск не сбивает цикл.
- **Подбор упражнений ИИ (Claude).** Учитывает историю, восстановление мышц, чередование между днями, оборудование, ограничения и цель. Без ключа или без интернета работает генератор на правилах.
- **Журнал.** Есть кнопки ±шаг веса, ±1 повтор и «повторить прошлый подход», а также RPE, разминочные подходы и заметки. Таймер отдыха в конце подаёт сигнал вибрацией или звуком, новые рекорды отмечаются уведомлением.
- **Прогресс.** Тоннаж, рабочие подходы по группам с коридором 10–20, расчётный 1ПМ по Эпли с графиком, личные рекорды.
- **Тело.** Вес, % жира, обхваты, ИМТ, графики, сравнение двух дат, фото «до/после».
- **Бэкап.** Экспорт и импорт всех данных в JSON, экспорт истории в CSV.

## Запуск

Нужен Node.js 20+.

```bash
npm install
```

```bash
npm run dev
```

Откройте адрес из консоли. Флаг `--host` уже включён, поэтому с телефона в той же Wi-Fi-сети можно зайти по `http://<IP-компьютера>:5173`. Service worker и установка на экран работают только по HTTPS (или на `localhost`), поэтому PWA целиком проверяйте на задеплоенной версии.

Другие команды:

```bash
npm test          # юнит-тесты (Vitest)
```

```bash
npm run build     # проверка типов + сборка в dist/
```

```bash
npm run preview   # локальный просмотр собранной версии (с service worker)
```

## Бесплатный деплой

Приложение собирается в статические файлы (`dist/`), поэтому подходит любой статический хостинг. Роутинг идёт через `#/...`, так что настраивать перенаправления на сервере не нужно.

### GitHub Pages

1. Создайте репозиторий на GitHub и запушьте проект в ветку `main`.
2. В репозитории откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**.
3. Workflow `.github/workflows/deploy.yml` уже лежит в проекте. Он прогоняет тесты, собирает проект с `BASE_PATH=/<имя-репозитория>/` и публикует его.
4. Через пару минут приложение будет доступно по адресу `https://<логин>.github.io/<имя-репозитория>/`.

### Vercel

1. Зайдите на [vercel.com](https://vercel.com), нажмите **Add New → Project** и импортируйте репозиторий.
2. Framework Preset: **Vite**. Build command `npm run build`, Output directory `dist` (подставятся сами).
3. Нажмите Deploy.

### Netlify

1. Зайдите на [app.netlify.com](https://app.netlify.com) и нажмите **Add new site → Import an existing project**.
2. Настройки сборки уже есть в `netlify.toml` (`npm run build`, папка `dist`).
3. Можно и без Git: выполните `npm run build` и перетащите папку `dist` на страницу **Sites → Deploy manually**.

## Установка на телефон

**iPhone (Safari):** откройте адрес приложения, нажмите «Поделиться» и выберите **«На экран „Домой“»**.
**Android (Chrome):** откройте адрес, затем меню ⋮ → **«Установить приложение»** (или «Добавить на главный экран»).

После первой загрузки приложение работает без интернета.

Важно про хранение данных:
- Данные живут в хранилище браузера. Если очистить данные сайта или удалить приложение с экрана «Домой» (на iOS), они пропадут. Регулярно делайте бэкап: **Ещё → Настройки → Резервная копия**.
- На iOS ставьте приложение на экран «Домой»: у сайтов, открытых просто в Safari, система может удалить данные, если ими долго не пользоваться.
- Вибрация в конце отдыха работает только на Android, на iPhone таймер подаёт звуковой сигнал.

## API-ключ Anthropic

1. Зарегистрируйтесь на [console.anthropic.com](https://console.anthropic.com).
2. В разделе **Billing** пополните баланс: API оплачивается отдельно от подписки Claude.ai.
3. В разделе **API Keys** нажмите **Create Key** и скопируйте ключ (`sk-ant-...`).
4. Рекомендуется сделать для приложения отдельный ключ и задать ему лимит расходов (**Limits** или workspace с лимитом).
5. В приложении: **Ещё → Настройки → ИИ (Claude)**. Вставьте ключ и нажмите «Проверить ключ».

Ключ хранится только в IndexedDB на устройстве. Запросы идут из браузера напрямую в `api.anthropic.com` (SDK отправляет заголовок `anthropic-dangerous-direct-browser-access: true`). Любой, у кого есть доступ к телефону, технически может прочитать ключ, поэтому лимит расходов нужен обязательно. В JSON-бэкап ключ попадает, только если включить отдельную галочку.

Модель по умолчанию — `claude-sonnet-5-5`. В настройках можно выбрать Haiku 5.5 (дешевле) или Opus 5.5 (умнее) либо ввести любой ID модели. Там же задаётся «глубина размышлений» (`effort`): по умолчанию низкая, так быстрее и дешевле.

## Как устроен подбор упражнений

```
src/generator/context.ts  — сбор контекста: слоты дня, восстановление мышц, соседние тренировки,
                            история за N недель, чередование между днями, оборудование, цель
src/generator/rules.ts    — генератор на правилах (работает без сети)
src/ai/prompt.ts          — системный промпт с правилами тренера + текстовый контекст
src/ai/schema.ts          — zod-схема ответа и смысловая проверка (слоты, id, оборудование, диапазоны)
src/ai/client.ts          — вызов SDK: structured outputs, повтор с ошибками валидации (до 3 попыток),
                            обработка отказов и ошибок API
src/generator/run.ts      — оркестрация: ИИ → при любой ошибке правила → сохранение в БД
```

Обе стратегии подбора опираются на одни и те же правила:
- базовые упражнения идут первыми;
- двойная прогрессия: если в прошлый раз во всех рабочих подходах достигнут верх диапазона, вес растёт на шаг;
- если прогресса нет 3 тренировки подряд, упражнение заменяется или назначается разгрузка (−10%);
- если с прошлой нагрузки на группу прошло меньше 48 часов, объём снижается и показывается предупреждение;
- упражнения, сделанные в другом дне цикла на ту же группу, не повторяются, а упражнения из прошлой такой же тренировки сохраняются ради прогрессии.

Ответ модели — строгий JSON по схеме (structured outputs), который затем проверяется через zod и правила приложения. Если проверка не прошла, модель получает список ошибок и повторяет попытку. После трёх неудачных попыток, при отказе модели, ошибке сети или неверном ключе приложение молча переключается на генератор по правилам и сообщает об этом короткой подсказкой. Для Sonnet 5.5 и Opus 5.5 включён серверный fallback: если модель отказалась отвечать, запрос автоматически повторяется на другой модели.

## Структура проекта

```
src/
  db/          Dexie-схема, сиды (80 упражнений, шаблон цикла), репозиторий, бэкап/CSV
  domain/      чистая логика: цикл, расписание, статистика, прогрессия, единицы, антропометрия
  generator/   контекст и генератор на правилах
  ai/          интеграция с Claude
  features/    экраны: today, workout, calendar, template, progress, body, settings, more
  components/  общие UI-компоненты, таймер, выбор упражнений
  hooks/       настройки, таймер отдыха, wake lock
```

Модель данных: `settings`, `cycleDays` (шаблон со слотами), `exercises`, `workouts` (дата + день цикла + статус), `workoutExercises` (заполненные слоты с целями), `sets` (подходы, сохраняются сразу), `bodyEntries`, `photos`. Веса хранятся в килограммах, в фунты пересчитываются только при отображении.

## Тесты

`npm test` проверяет:
- логику цикла и «следующего дня», пропуски и счётчик циклов;
- генератор на правилах: слоты, типы, оборудование, чередование, прогрессию, застой, правило 48 часов;
- валидацию ответа ИИ и вызов модели с замоканным SDK (повторы, отказ);
- тоннаж, объём по мышцам, 1ПМ, рекорды;
- бэкап (экспорт → импорт) и CSV.
